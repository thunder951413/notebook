# 坚果云同步协议 v5 设计

状态：v4.1 低流量与有界历史已实现；v5 分段协议设计冻结，但尚未启用。

## 1. 为什么不能继续扩展单文件日志

v4 为每台设备维护一个 `journal/<deviceId>.jsonl`。每次推送都要先下载整份文件、在本地追加，再把整份文件重新上传。4 MB 报错来自应用自己的保护上限，不是坚果云的单文件上限。v4.1 已用小型 head 和历史环消除空同步的大文件下载及无限 revision 增长，但以下长期问题仍然存在：

- 无变化拉取已经不再下载完整日志；但有本地变化时仍会读取并重传自己的完整压缩日志。
- 每次 PUT 都会在坚果云形成同一文件的新历史版本，消耗上传流量，但这些历史版本不能作为应用可查询的增量日志。
- `revision` 等历史实体使用唯一 ID，按 `type:id` 保留最新值的压缩无法缩减它们；最终仍会再次达到任意固定单文件上限。
- 坚果云对 WebDAV 有请求频控和目录分页限制。大量重复 MKCOL、对象逐个探测和超大目录扫描都会提前耗尽额度。
- v4 的设备日志彼此独立，没有全局顺序；仅靠设备序号和标量版本不能可靠表达跨设备因果关系。

### 当前已实现的 v4.1

```text
journal/<deviceId>.jsonl
journal/<deviceId>.head.json
objects/<first-two-hex>/<sha256>
```

- `syncOutbox` 是 Electron 的事务性本地变化标记；Android 使用 outbox count，并仅在 outbox 为空但 dirty count 非零时执行修复扫描。
- `head.json` 约数百字节，包含最后序号、日志字节数与 SHA-256。无变化时只做目录 PROPFIND 和每设备一次小 head GET，不下载 `.jsonl`。
- journal 先写、head 后写；只有 head 成功才确认 outbox。读取端只消费 head 已提交的序号前缀。
- 非 `revision` 实体始终只保留每个 `type:id` 的最新状态，包括删除墓碑。
- 远端 revision 环每设备最多 256 条且序列化总量最多 2 MiB；Electron 本地每页最多保留 50 个自动版本和 20 个手动/导入版本。
- 完整 document payload（包括规范 Markdown）超过 2 KiB 后按 SHA-256 外置，journal 只保留小标记；下载端校验对象 hash。Android 在有待发布变更时会校验同 hash 的远端对象，发现损坏后重传；无变化轮次不会访问对象。单轮同步复用客户端和目录缓存。
- Electron、Android 和 Python 本地桥使用同一 head 字段、UTF-8 字节计算和历史环规则；缺少 head 的旧 v4 日志仍可读取。

v4.1 仍不是最终协议：有变化时会完整重写自己的日志；全局 `objects/` 尚无跨设备安全垃圾回收；旧版本客户端在已存在 head 后继续写入会留下未提交尾部，需由新版所属设备再次发布 head；设备日志仍没有全局因果顺序。因此 v5 仍有必要。

## 2. 坚果云约束

设计按坚果云帮助中心当前公开约束取保守值：

- WebDAV/网页端默认单文件上传上限为 500 MB。
- 免费版每 30 分钟最多 600 次 WebDAV 请求，付费版最多 1500 次。
- 单次目录请求最多返回 750 个文件或目录；客户端不能依赖列出一个无限增长的目录。
- 免费版每月上传流量 1 GB、下载流量 3 GB；付费方案的流量策略不同，但协议不应以高流量为前提。
- 文件历史版本适合人工灾难恢复。个人免费版、个人付费版、团队版的保证保留期分别为约 1 个月、3 个月、至少 6 个月，不能作为应用永久历史。

## 3. 设计目标

1. 日常推送只上传本次变化，不重写历史数据。
2. 日常拉取只下载新段；未变化设备最多读取一个很小的头文件，并可使用 ETag 得到 304。
3. 任一提交在掉线、超时和重试后都满足“完整可见或完全不可见”。
4. 新设备可从快照恢复当前状态，并按需读取完整应用历史。
5. 多设备并发不依赖服务器锁，也不以文件修改时间作为唯一顺序。
6. 目录中的活动文件数量有硬上界，不触发 750 条分页陷阱。
7. Electron、Android 和浏览器桥使用同一字节级、哈希级和加密级契约。

## 4. 远端布局

```text
<remotePath>/
  protocol.json
  devices/
    <deviceId>/
      head.json
      segments/
        <generation>-<firstSeq>-<lastSeq>-<sha256>.jsonl
      snapshots/
        <generation>-<lastSeq>-<sha256>.jsonl.gz
  objects/
    <first-two-hex>/<sha256>
  quarantine/
```

规则：

- `segment`、`snapshot` 和 `object` 都是不可变文件；相同路径只能写入相同字节。
- 每台设备只覆盖自己的 `head.json`，保持单写者边界。
- 拉取端不列出 `segments/` 或 `snapshots/`；所有活动路径由 `head.json` 明确给出，因此目录条目数不影响正确性。
- 旧段在应用保留期内不删除。清理只删除已被已提交快照覆盖、超过保留期且不再被任何活动头引用的文件。

## 5. 设备头与提交点

`head.json` 是一台设备唯一的可变提交点：

```json
{
  "schemaVersion": 5,
  "deviceId": "uuid",
  "generation": 3,
  "lastSeq": 1842,
  "updatedAt": "2026-08-07T00:00:00.000Z",
  "snapshot": {
    "lastSeq": 1600,
    "path": "devices/<id>/snapshots/3-1600-<hash>.jsonl.gz",
    "sha256": "...",
    "byteSize": 123456
  },
  "segments": [
    {
      "firstSeq": 1601,
      "lastSeq": 1660,
      "path": "devices/<id>/segments/3-1601-1660-<hash>.jsonl",
      "sha256": "...",
      "byteSize": 45678
    }
  ]
}
```

推送顺序：

1. 读取并校验自己的 `head.json`；本地缓存 ETag 时使用条件 GET。
2. 上传内容对象和新的不可变 segment。
3. 校验上传字节的 SHA-256。
4. 最后 PUT 新 `head.json`。只有这一步成功后才确认本地 outbox。
5. 若 PUT 支持强 ETag，则携带 `If-Match`；收到 412 时重新读取头并重放。若坚果云实测不支持，则退回设备单写者约束和进程内互斥。

在第 4 步之前失败只会产生不可见的孤儿文件，不会产生半次同步。孤儿由延迟清理回收。

## 6. segment 格式与因果历史

每条变更必须携带稳定的操作 ID 和父版本引用，而不是只携带设备内序号：

```json
{
  "seq": 1842,
  "operationId": "uuid",
  "deviceId": "uuid",
  "ts": "2026-08-07T00:00:00.000Z",
  "type": "document",
  "id": "page-uuid",
  "op": "upsert",
  "parent": {
    "deviceId": "uuid",
    "seq": 1830,
    "segment": "devices/...jsonl",
    "entryHash": "sha256"
  },
  "entryHash": "sha256",
  "payload": {},
  "objectHash": "optional-sha256"
}
```

- `entryHash` 对规范化后的变更内容计算，重试不会制造新的逻辑变更。
- `parent` 指向编辑时看到的实体版本。父版本相同而出现两个不同子版本时是真并发，必须形成冲突，不允许用设备 ID 排序静默覆盖。
- 单一路径上的后代可以直接替代祖先；多分支保留所有头，待用户或自动合并产生一个以双方为父的新版本。
- `revision` 是应用实体，和传输 segment 是两层概念。手动版本、保留的导入历史和受限数量的自动保存版本继续作为实体同步；传输压缩不得删除它们。

第一版实现可继续使用现有 outbox，但必须把标量 `syncVersions` 升级为可持久化的版本引用；在该迁移完成前不得宣称 v5 已解决并发覆盖。

## 7. 快照与历史保留

触发任一条件时为本设备生成快照：

- 活动 segment 达到 64 个；
- 活动 segment 总字节达到 8 MB；
- `head.json` 达到 128 KB；
- 用户主动执行仓库维护。

快照包含截至 `lastSeq` 的最新实体头、删除墓碑和版本引用，按 UTF-8 JSONL 排序后 gzip。快照不替代应用历史：

- 当前状态恢复只需快照和快照后的 segments。
- 版本历史通过实体的父引用按需读取旧 segment；因此历史数据不能只依赖坚果云的文件历史功能。
- 自动保存历史继续执行产品上限；删除历史时要发布明确 tombstone，不能只删本地数据库。
- 默认只自动删除 90 天以前、已被快照覆盖且不再被活动版本链引用的传输段。该值必须可配置，且删除前生成可审计清单。

## 8. 拉取流程

1. PROPFIND `devices/`，只枚举设备目录。设备数超过安全阈值时停止并提示维护，不能静默截断。
2. 对每台设备条件 GET `head.json`；304 时不做后续请求。
3. 若本地游标早于快照，下载并校验快照；否则只下载 `lastSeq` 大于本地游标的 segment。
4. 所有文件先校验声明字节数、SHA-256、设备 ID、序号范围和 JSON schema，再进入本地事务。
5. 只在本地事务实际提交后推进该设备游标。遇到冲突时保存冲突分支；不得推进越过尚未持久化的记录。
6. 推送成功后只需再次条件读取发生变化的设备头，而不是重新下载全部设备日志。

## 9. 请求与流量预算

正常一次无变化拉取：

- 1 次设备目录 PROPFIND；
- 每台设备 1 次条件 GET，通常返回 304；
- 0 次 segment 下载。

正常一次有本地变化的推送：

- 0 或 1 次自己的 head GET；
- 每个新增二进制对象 1 次 PUT；同一次批次的元数据和正文变更合并为少量 segment PUT；
- 1 次 head PUT。

客户端必须实现：

- 尊重 `Retry-After` 的 429/503 指数退避和全抖动；认证、schema、哈希错误不得重试。
- 同一同步轮次的目录创建缓存；目录缺失时再补建，不能对每个对象重复 MKCOL 根路径。
- 对象上传去重采用本地已发布哈希缓存；是否用远端 HEAD/PROPFIND 再确认，要根据“省流量”和“省请求”的账户策略选择。
- 单批 segment 建议 256 KB 至 1 MB；不能为了减少请求制造接近 500 MB 的大文件。

## 10. 隐私与加密

当前代码仍保留 `syncPassword` 配置用于未来协议，但不会把它误当作已完成的加密实现。Electron 和 Android 都已把隐私笔记本/文件夹及其页面、正文、历史、附件、待办步骤、标签关系和阅读位置设为本机专有，并在界面明确不上传。它保证不产生明文泄漏，但不提供跨设备隐私笔记同步。v5 启用前必须统一：

- 仓库级随机 salt；PBKDF2-SHA256 参数、AES-256-GCM、nonce 长度和 AAD 的跨端固定测试向量。
- 隐私实体的标题、正文、版本历史和内部元数据均进入密文；远端只保留路由所需的最小标识和密文哈希。
- 附件是否端到端加密必须在产品界面明确说明；不能把 WebDAV 账号保护描述为内容加密。
- 密码错误或缺失时停止应用相关变更，不推进游标，也不删除 outbox。

## 10.1 客户端低频发布契约

本地持久化和远端发布必须分层，不能为了节省 WebDAV 流量而把未保存正文留在内存中：

| 变化 | 本地处理 | 远端处理 |
| --- | --- | --- |
| 正文编辑 | 草稿立即写入，稳定正文短延迟写入数据库 | 最后一次变化后 30 秒发布；同页 page/document outbox 覆盖合并 |
| 自动历史 | 本地按页保留固定循环窗口 | 同一发布窗口内，每页只保留最新一个未发布 autosave；手动/导入版本不合并 |
| 阅读/滚动位置 | 只更新本地数据库、内存或本机恢复缓存 | 仅在应用失焦/进入后台或桌面端退出时进入 outbox |
| 标题、标签、目录、任务步骤 | 立即写本地数据库 | 30 秒静默窗口合并发布 |
| 附件 | 先原子写入本地文件和元数据 | 30 秒静默窗口发布；按内容哈希去重 |
| 光标、选区、面板宽度、展开状态、最近列表 | 本机设置 | 永不上传 |
| 搜索索引、AI 派生索引、诊断日志 | 本机可重建/有界数据 | 永不上传 |

触发边界：

- 应用获得焦点/回到前台时立即执行一次增量拉取，并顺带发布已有 outbox。
- 应用失去焦点/进入后台时，先落草稿和 dirty 阅读位置，再立即请求同步；多个生命周期事件必须合并成一次运行。
- Electron 退出可以暂缓窗口关闭，等待有限时长的本地 flush 和网络同步；超时或失败必须保留 outbox，不能阻止后续恢复。
- Android 不承诺进程退出时网络必达。`onStop` 只负责把状态持久化并提交 WorkManager；强制停止或系统杀进程后由下次启动补偿。
- 网络恢复和应用启动保留一次安全增量拉取；手动“立即同步”不受 30 秒窗口限制。
- 页面切换不触发网络同步，也不发布阅读位置；它只负责本地页面状态切换。

## 11. v4 到 v5 的迁移

采用显式、可回滚的迁移，不允许某一端悄悄切换布局：

1. 所有已支持 v5 的客户端先保持 v4 读写，并在 UI 显示仓库协议状态。
2. 迁移协调端完整读取 v4 journals，校验并构建 v5 基线快照；v4 原文件只读保留。
3. 写入 `protocol.json` 的 `migrationId`、v4 指纹和 v5 基线哈希，再由第二个客户端只读验证。
4. 验证通过后把 `writeProtocol` 切到 5；过渡期可双写一个受限的 v4 压缩镜像，直到所有登记设备都报告 v5 能力。
5. 旧客户端尝试写入 v4 时必须得到“需要升级”而不是继续形成分叉。
6. 至少经过一个坚果云历史保留窗口或用户明确确认后，才允许清理 v4 文件。

迁移验收必须比较：实体数、墓碑数、版本历史数、附件数与哈希、每台设备最后序号、隐私密文可解性。

## 12. 分阶段落地

### 阶段 A：v4 安全修复

- 已超 4 MB 的日志可由所属设备读取并压缩；每次写入都会生成最新状态投影。
- 远端历史为 256 条/2 MiB 循环 buffer，当前状态和删除墓碑不参与历史淘汰；100 MB 只保留为损坏/滥用安全上限。
- 小型 head 是发布提交点；无变化时不读取 journal 正文。
- 本地 outbox/count 是数据库变化标记，不扫描或 hash 全库。
- 大对象按 SHA-256 去重，单轮目录创建有缓存。
- 所有上限按 UTF-8 字节计算。
- 压缩前的 10 万条保护不再形成无法自救的死锁。
- 冲突时只推进实际提交的 WebDAV 游标。
- 只确认真正写入日志的 outbox 项。
- 这些修改解决当前故障、空同步流量和 revision 无限增长；有变化时的整日志重写、对象垃圾回收和跨设备因果关系留给 v5。

### 阶段 B：v5 纯协议与契约测试

- 在共享 fixtures 中冻结 head、segment、snapshot、哈希、gzip、父引用和加密测试向量。
- Electron/Android/Python 对同一 fixture 产生逐字节一致的规范结果。
- 用故障注入覆盖 segment 已写/head 未写、重复 PUT、412、429、目录截断和损坏对象。

### 阶段 C：只读 v5 与迁移演练

- 新客户端先支持读取 v5，不写入。
- 在测试目录运行 v4→v5 迁移并做三端恢复、冲突和历史验收。

### 阶段 D：切换写入与清理

- 双端版本满足最低要求后切换 v5 写入。
- 保留 v4 回滚窗口、迁移报告和用户可见的仓库维护入口。

## 13. v5 上线门槛

- 10 万次编辑后，任一活动 head 小于 128 KB，正常增量同步不随总历史线性增长。
- 模拟免费版 600 请求/30 分钟预算时，典型编辑和打开笔记不会触发频控。
- 任意网络故障点重试后，远端状态等价于提交前或提交后，不出现半提交。
- 两设备离线编辑同一实体后能稳定产生冲突，处理顺序不同也不会静默丢失任一分支。
- 全新 Electron 和 Android 设备都能从快照恢复当前内容、附件和版本历史。
- 隐私测试向量跨三端一致，错误密码不泄漏明文且不推进游标。
- v4 原仓库在整个迁移与回滚窗口内保持可恢复。

## 14. Android 真机安全回归基线

2026-08-07 在 OPPO PKJ110、Android 16（API 36）上，以独立包名 `io.github.notebook.android.nexttest` 和只监听 `127.0.0.1` 的内存 WebDAV 夹具完成以下验证；正式包和真实坚果云目录未被修改：

- 首次发布后删除本地记录、轮换设备 ID，可以从 journal/objects 完整恢复标题和正文。
- 无变化同步只有目录检查和小型 `.head.json` GET，没有 `.jsonl` GET、journal/object PUT。
- journal PUT 返回一次 503 时 outbox 与 dirty 标记保留；下次同步成功后才确认并清空。
- 已存在的内容寻址对象被替换为错误字节后，下一次发布会检测 SHA-256 不匹配并修复对象，再提交 journal。
- 真实 `force-stop` 后移除 ADB 网络通道，从新进程同步失败仍保留 outbox；恢复网络后发布成功，并可由新游标回放。
