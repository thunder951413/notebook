# 同步异常隔离与处理方式（WebDAV v4.1）

日期：2026-10-18。对应评估报告 `docs/audits/2026-10-17/sync-reliability.md` 的 F1、F8，以及 F4/F11 的一部分。

## 原则

1. **失败范围取最小。** 读不懂的数据只影响它自己：一条记录进入隔离区，一台设备的日志标为 blocked；其他记录、其他设备照常同步。
2. **只隔离"数据问题"。** 网络、认证、服务器错误、超时、取消仍然让整轮失败——它们不说明任何一条数据有问题，隔离只会掩盖故障。
3. **不丢、不静默。** 被隔离的记录连同读取位置在同一个事务里保存，可重试；同步结果带 `issues`，界面不再显示纯粹的"已同步"。
4. **三端同一套原因码。** blocked 原因码由共享 fixture `pull-isolation.json` 约束；隔离原因码三端一致。

## 设备级：blocked

| 原因码 | 场景 | 处理 |
| --- | --- | --- |
| `journal-corrupt` | 日志有无法解析的行 | 该设备整体 blocked，不读取其记录；其他设备不受影响 |
| `head-corrupt` | 提交标记无法解析 / 设备 ID 不符 / 版本不支持 | 同上 |
| `journal-truncated` | 日志序号小于标记的 `lastSeq`（已提交的记录丢失） | 已有的完整行照常应用，读取位置只推进到实际读到的序号；设备标 blocked。已追平标记的读取端用 PROPFIND 的文件大小发现截断 |
| `journal-missing` | 标记存在但日志文件不存在且有未读记录 | blocked（本机自己的日志缺失由"自动重新上传"处理，不报告） |
| `journal-too-large` | 日志超过 100 MB | blocked |

尾部未提交（日志比标记长）不是问题，只读已提交部分。

## 记录级：隔离区（syncQuarantine）

| 原因码 | 场景 | 自动重试 | 用户操作 |
| --- | --- | --- | --- |
| `needs-key` | 私密记录但没配置同步密钥 | 配置密钥后的下一次同步 | 填写与其他设备相同的同步密码 |
| `bad-key` | 密钥不匹配或密文损坏 | 同上（最多 5 次） | 确认各设备密钥一致 |
| `unknown-type` | 更新版本写入的未知类型 | 应用支持该类型后 | 升级应用 |
| `invalid-payload` | 缺字段、id 不匹配、路径穿越的 id、版本不对 | 每次启动一次 | 升级应用；仍失败导出诊断日志 |
| `workspace-mismatch` | 属于其他工作区 | 不重试 | 可删除 |
| `missing-object` | 正文/附件对象 404 | 最多 5 次 | 在产生该内容的设备上"重新上传本机全部内容"，再重试 |
| `object-corrupt` | 对象哈希不符 | 最多 5 次 | 同上 |

- 桌面端存于 IndexedDB `syncQuarantine`（Dexie v21），与读取位置同事务提交；上限 1000 条，超过则停止拉取并提示（不静默丢弃）。
- Android 存于 SharedPreferences（`webdav-quarantine:<仓库>`），先存隔离区、后推进读取位置；崩溃只会重读（幂等）。
- 设置页"同步状态与修复"列出问题与处理建议，可"重试"或（确认后）"删除"。删除只丢弃本机的隔离副本，不改动云端。

## 已知限制（后续）

- **自己的日志损坏时无法再上传：** 追加前要先解析现有日志，解析失败则写不进去。需要"重建本机日志"（保留损坏文件、用 `minSeq` 保持序号）的修复入口。
- **标记落后于日志的修复（F10）、强制重传损坏对象（F11）** 尚未提供，目前只能在产生内容的设备上"重新上传本机全部内容"。
- Electron 传输层依赖 `webdav` 库，缺少 `getcontentlength` 时按"未知"处理，空日志只有在被读取时才会发现。
- Android 目前不检测"只有提交标记、没有日志文件"的设备。
