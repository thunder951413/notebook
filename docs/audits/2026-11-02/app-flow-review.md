# 桌面应用功能与使用流程走查（2026-11-02）

范围：共享渲染层 `cross-platform/apps/renderer`（Tauri 主壳与已废弃的 Electron 壳共用）。方法：逐个读组件和 hooks 走查代码，按使用流程追踪状态变化，再跑类型检查、lint 和 379 个渲染层测试。沙箱禁止监听本地端口，开发服务器起不来，所以**这次没有在真实窗口里点过**，结论全部来自代码和测试。

## 2. 使用流程，以及这次改了什么

### 2.1 打开一篇笔记
列表单击打开、双击打开并聚焦正文；页面树点击打开；命令面板、反向链接、AI 结果、子笔记总览、全文检索、前进后退都能打开笔记。

**问题：** 列表和树会关掉抽屉、在窄布局下切到编辑器，并离开待办/回收站集合；其余入口统一走 `openRecentPage`，这三件事都没做。窄窗口里从命令面板打开笔记，界面还停在列表；从待办集合打开笔记，列表仍是待办；AI 助手也不让开。
**修复：** `openRecentPage` 现在也会调用 `onPageActivated`。App 里的 `onPageActivated` 会关闭 AI 助手、把待办/回收站集合换回全部笔记，再按布局把编辑器带到前面（`revealEditor`）。

### 2.2 新建
⌘N 在当前集合里新建；命令面板可以新建页面、日记、模板、剪藏；还有全局快速记录。

**问题：** 模板、日记、剪藏、快速记录只设了 `activePage`，没设笔记本和分区，也没把编辑器带到前面。快速记录在待办集合里触发时，列表还是待办。
**修复：** 新增 `showNewPage(pageId, sectionId)`。刚建好的页面可能还不在库快照里，所以按 id 和分区直接显示，同时设好笔记本，离开待办/回收站集合，并带出编辑器。

### 2.3 新建笔记本
**问题：** 建完以后只展开新笔记本，列表和选中项都没变，用户看不到它；空笔记本的页面树什么都不显示，也没有下一步提示。
**修复：** 建完直接进入这个笔记本（`chooseScope`）。空笔记本在边栏显示“还没有页面 · 新建页面”。

### 2.4 删除与撤销
**问题 1（已有缺陷）：** 列表删除后会打开相邻笔记，相邻笔记可能在另一个分区；点“撤销”恢复后只设回了 `activePage`，`activeSection` 还指着别的分区。`hasActivePage` 要求页面所在分区等于 `activeSection`，所以编辑器显示“选择一篇笔记”。回收站详情页的“恢复页面”按钮也有同样的问题。
**修复：** 撤销和“恢复页面”都改为连同页面自己的分区一起选中；待办则回到待办。

**问题 2：** 在命令面板里“将当前页面移到回收站”，面板先确认一次；如果页面有引用或子页面，`trashPage` 再确认一次，而且没有撤销提示。
**修复：** 命令面板和列表、编辑器菜单走同一条路径：只有影响链接或子页面时才确认，其余情况直接移动并给出可撤销的提示。

**问题 3：** 待办在编辑区的“更多操作”里没有“移到回收站”，只能在列表里右键删除。**修复：** 补上了。

### 2.5 AI
**问题：**
- AI 助手、AI 收纳里的“配置 AI”和命令面板里的“AI 与协作服务”都打开了“同步与连接”页，而模型设置实际在“AI 与自动化”页。这个流程是断的。
- 命令面板里没有 AI 助手，只有“打开 AI 工作区”，而它打开的是另一个界面（校订台）。
- 编辑器工具栏的 AI 按钮在待办和回收站里也会显示，此时传进去的是待办或已删除页面。

**修复：** 三处“配置 AI”都改为打开 `automation` 页；`SettingsPageId` 从 SettingsCenter 导出，App 和命令面板共用。命令面板新增“打开 AI 助手”，原入口改名为“打开 AI 校订台”并补充说明。AI 按钮只在有打开的笔记时显示。

### 2.6 对话框与键盘
**问题：** 新建、重命名、移动、导入、加密备份、隐私密码、插入双链这 7 个对话框按 Esc 都关不掉（设置、确认框、命令面板可以）；标题框按 Enter 没有反应，只有失焦时才保存。
**修复：**
- 新增 `components/dialogKeys.ts` 里的 `closeOnEscape`，挂在对话框元素上。只有拿到焦点的那层对话框会响应，输入法组字时不响应，事件也不会再传到窗口级快捷键（比如退出专注模式）。
- 标题框按 Enter 保存并回到正文，按 Esc 放弃修改。

### 2.7 文案与一致性
- 命令面板“同步与连接”的副标题还写着“SSH/SFTP 服务器设置”，“立即同步”的关键词也还是 ssh/sftp：已改成坚果云 WebDAV。
- 设置里的“Electron 桌面版……”文案已改为“桌面版”，钥匙串或凭据管理器按平台显示。
- 安全说明里写着“跨设备隐私同步将在统一的加密协议完成后启用”，这与已经上线的隐私同步密钥矛盾，已改成现在的实际行为。
- 页面树菜单写“收藏”，列表和边栏写“置顶”，操作的是同一个 `favorite` 字段：统一为“置顶”。

## 3. 实现评估

| 方面 | 评价 |
| --- | --- |
| 数据与同步 | 最扎实的部分：本地优先，崩溃草稿、退出保存握手、隔离区、日志重建、三端共用 fixtures，测试也覆盖得多。 |
| 列表与搜索 | 虚拟列表、拼音懒加载、可中止的全文检索、悬停预取，性能考虑到位。 |
| 大文档 | 有专门的阅读器、分章编辑和 worker 索引，已经有效避开导入和打开时的卡死。 |
| **App.tsx** | **最大的风险。** 1,500 行、约 60 个 `useState`，集中了导航、对话框、AI、同步修复、快捷键。这次修的几个流程问题都出在这里。 |
| 选择状态 | `activeArea`、`scope`、`browse`、`stackView`、`navOpen/pagesOpen`、`drawerOpen`、`activeNotebook/Section/Page` 彼此重叠，要靠每个入口手动同步。`hasActivePage` 依赖 `activeSection === page.sectionId`，任何入口漏设分区就会显示空白。 |
| 对话框 | 都是手写的 `settings-backdrop`，没有共用外壳：焦点不困在对话框内，`aria-modal` 有的有有的没有，这次补上 Esc 也只能逐个加。 |
| AI 界面 | 三套界面（助手、校订台、收纳），提案审阅又在设置里出现一次（`AutomationWorkspaceReview`），概念和代码都有重复。 |
| 重复代码 | 从 Markdown 生成预览的正则在 App.tsx 里复制了 3 份；新建并写入正文的流程也有 3 份（模板、AI 建笔记、`planApi`）。 |
| 小问题 | `usePageNavigation.selectArea` 已经没人用；`syncRepair` 依赖 `pages`，每次库变化都会重建；冲突副本靠标题里的“（冲突副本”识别，比较脆弱；`currentDocumentIsEmpty` 每次编辑都把整篇文档序列化成 Markdown。 |

## 4. 建议的后续工作（未做）

1. **选择状态收敛（优先）**：用一个 reducer 管 `{ scope, pageId }`，分区和笔记本从页面推出来，删掉 `activeSection` 这个独立状态。所有打开、新建、恢复都走一个 `open(pageId, { reveal })`。这能从根上消掉 2.1、2.2、2.4 这一类问题。
2. **拆 App.tsx**：对话框宿主、列表处理器、编辑器工具栏、同步状态菜单各自成为组件或 hook。
3. **共用对话框外壳**：统一提供焦点困住、Esc、点背景关闭和 `aria-modal`，替换掉 7 个手写对话框。
4. **AI 入口合并**：把校订台作为 AI 助手里的一个标签页，或者至少在边栏给它一个入口；设置里的提案审阅指向同一个界面。
5. **日记位置**：现在日记建在当前分区，在哪个分区触发就散落在哪里。可以考虑固定放到一个“日记”顶层页面下。
6. **真机走查**：在允许本地端口的环境里跑 `pnpm tauri:dev`，按第 2 节的流程逐条在宽、中、窄三种布局下点一遍。
