# Notebook Android 系统笔记风格改版实施计划

目标是在现有 Notebook Android 上还原 ColorOS 系统“笔记”的主要布局、交互状态和切换效果，继续使用现有笔记、Markdown、附件、历史和同步能力。用户已确认学习结果并于 2026-10-11 授权全面实施。会议实时转写、AI 实际生成、OCR 实际处理和大字体专项适配移出范围；普通录音附件、深色主题与现有数据能力继续保留。

设计依据为 [实机研究](android-ui-reference-study.md) 和 [本地界面与动效浏览册](/Users/surfing/tools/notebook/output/android-reference-study-2026-10-11/index.html)。实现先建立可靠的状态转换及编辑闭环，再根据实机截图和录屏调整视觉。实现只开放有实际功能的数据与媒体入口。

## 产品结构

手机首页采用“笔记／笔记库”双标签，并提供待办与创建的独立入口。把文件夹呈现为彩色封面的笔记库，笔记详情采用阅读优先，再进入编辑。现有待办、提醒、历史、同步冲突、私密库、子页面和双链继续可达，放在对应筛选、更多菜单、库类别或详情面板中。

页面的主要关系为：

```text
笔记首页 ↔ 笔记库首页 → 笔记库详情
     ↓             ↓          ↓
 全局搜索       库内搜索    添加来源／已有笔记选择器
     ↓                        ↓
   笔记阅读 ←───────────────────┘
     ↔ 编辑 → 格式／引用／附件／添加块
     → 目录／查找／标签／历史／分享与导出

首页更多 → 最近删除 → 已删除笔记预览 → 恢复／彻底删除
首页更多 → 设置 → 同步／编辑偏好／录音附件
```

当前 folder、notebook、section 和页面树之间已有对应关系。普通笔记库优先映射现有文件夹实体及 color 字段；需要先核对跨库归属，不能仅凭界面“添加”就引入多对多实体。普通正文内的勾选项映射 Markdown 任务列表，独立的提醒待办继续保留原有实体和调度语义。

## 状态与返回规则

用明确的页面、编辑模式和浮层状态替换分散的布尔开关。状态需要携带笔记／笔记库 ID、来源页面、选中项、搜索范围、滚动位置、正文选区和待保存版本。

| 状态 | 进入时的变化 | 返回或关闭 |
| --- | --- | --- |
| 全局或库内搜索 | 顶部入口展开、底部导航收起、明确搜索范围 | 先处理输入法，再退出搜索并恢复原列表位置 |
| 多选 | 标题变为数量、卡片出现选框、底部切换批量操作 | 退出选择，不触发数据操作 |
| 阅读 | 完整正文、目录、分享、更多、编辑胶囊 | 返回来源首页、搜索或笔记库 |
| 编辑 | 顶部撤销／重做／完成，底部编辑工具，保持同一文档 | 完成或结束编辑前刷新草稿；不同返回来源单独验证 |
| 格式或添加面板 | 保留正文光标，用面板替代键盘区域 | 恢复焦点、选区和之前的键盘状态 |
| 引用候选 | 一次命令管理触发符与候选 | 取消和撤销有可预测的正文结果 |
| 子菜单 | 保留淡化的父层 | 返回先关闭子层；点击外部关闭整个菜单 |
| 全屏表格 | 同一张表格、独立视图和方向状态 | 回到原编辑位置并恢复原方向 |
| 已删除预览 | 隐藏编辑入口，只开放恢复和彻底删除 | 返回回收站；恢复后原位转普通阅读 |

保存和导航不等待动画完成。返回、切预览、切笔记、切后台、导出、开始同步等边界直接调用已验证的刷新逻辑；失败时保留草稿并呈现失败状态。动画不能决定数据是否落盘。

## 编辑器与 Markdown 兼容

实现中最大的工作是把现有 Markdown 文本框转成可见格式的编辑体验，同时继续以规范 Markdown 保存和同步。先做编辑器方案验证，再完成整套工具面板，避免工具能改外观却不能正确保存。

方案验证至少包含中文组合输入、选区跨段、撤销重做、图片与引用占位、长文按需呈现、键盘升降和读写往返。外层采用 Compose；正文编辑实现应在现有 Android 原生编辑组件和受控富文本编辑层之间验证输入与序列化，选型结果以临时样本的可重复测试决定。

| 参考操作 | 持久化安排 |
| --- | --- |
| 标题层级、正文、粗体、斜体、删除线、列表、引用、代码、普通表格 | 优先映射已有规范 Markdown 能力 |
| 文内待办 | Markdown 任务项，与独立 Todo 的提醒属性分开 |
| 图片、音频、文件 | 沿用已有 asset 标识、哈希和应用私有资源，不写回临时 URI |
| 页面／块引用 | 沿用 NotebookReferenceSyntax，选择器负责插入而非生成另一套语法 |
| 字体、颜色、字号、下划线、对齐、特定高亮块 | 先确定可往返的表示；纯阅读偏好保存为本地偏好，正文语义样式须定义兼容扩展并补桌面端往返验证 |
| 全屏表格 | 共享同一表格模型，校验编辑、序列化、横竖屏及返回后的状态 |

尚未具备稳定往返表示的样式，不先开放为可保存的按钮。高亮、字体等扩展如需改变共享协议，须先列出跨端行为，再作为单独的数据契约工作处理。还要保留未知块和现有嵌入语法，避免将“看上去相似”变成同步后的信息丢失。

## 视觉与动效实现

先建立统一组件：圆形工具按钮、悬浮胶囊、笔记卡片、笔记库封面、空状态、分组设置、底部面板、叠层浮窗、选中标记和短时反馈。颜色以实机取样为基础；边距以约 16 dp、卡片间距约 12 dp 为起点，尺寸适应字号、附件和屏幕宽度。

不同页面使用对应的运动方式：

1. 卡片和笔记库进入详情：保存来源卡片位置，协调容器放大、圆角变化、背景淡化及内容出现；返回时恢复原列表位置。
2. 新建菜单：背景模糊、下方功能卡片出现、创建按钮变关闭，左侧入口随菜单状态变化。
3. 搜索：圆形入口展开为胶囊，输入框与取消同步出现，焦点和键盘只触发一次。
4. 底部面板：跟随拖动、松手归位或关闭，协调遮罩和背景层级；键盘面板切换优先保持正文稳定。
5. 叠层筛选：父菜单缩小和淡化，子菜单定位到当前选项，返回恢复父层。
6. 多选：卡片按压反馈、选框出现、标题数量和工具组转换保持一致。
7. 系统返回：兼容系统边缘提示，单独验证提交和取消，不依赖某品牌私有动画接口。

初始动效调参可从工具组 160–220 ms、浮层 220–300 ms、页面容器 280–360 ms 开始。这些是实现初值，不是参考应用的测量参数；最终按相同触发点的录屏逐帧对照修正。系统关闭动画时直接完成状态转换；模糊不可用的设备保留同样的层级、颜色与透明度关系。

本轮已按阶段 0–4 实施，设备验收依据用户后续选择优先在隔离模拟器完成。品牌云入口替换为 Notebook 的 WebDAV 设置及真实同步状态；会议转写、AI 生成、OCR 和大字体不在本轮实现范围。最终通过项、仍需真机校准的差异和产物地址以实施验收报告为准。

最终编辑方案采用受控 Markdown 源与原生内容块：文本样式通过可逆映射显示，图片、代码和表格按块呈现；跨块精确选区可切换源码模式，超长正文分页以限制原生布局规模。正文颜色、字体、下划线及对齐仍受跨端格式契约约束，本轮不开放这些按钮。

## 首次实现的具体切入点

从合并代码基线和一个最小编辑器验证样本开始。验证结果通过后，按“首页卡片 → 阅读 → 编辑 → 格式面板 → 完成 → 返回”的完整路径制作第一份 debug APK，同时保留保存、历史和同步日志。此路径能同时检验外观、状态、输入和持久化，也是后续扩展笔记库与媒体功能的共同基础。


## 2026-10-11 实施结果
