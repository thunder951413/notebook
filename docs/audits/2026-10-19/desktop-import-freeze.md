# Mac 首次删除与百万字 Markdown 导入卡顿

## 已确认范围

修复 Mac 桌面版首次删除笔记和导入大文档时的卡顿。用户提供桌面上的 `重生丹尊_全本.md` 作为复现文件；保留完整正文和现有单篇笔记工作流，复用现有存储、引用索引、后台解析和大文档显示机制。

## 原因与修复

- 删除确认在持久引用索引为空时调用全文检索以补查标题链接，首次操作会构建全库索引。`Promise.race` 的 400 毫秒定时器无法打断主线程同步计算，超时也不会取消后续工作。删除现在只查询已有引用索引；引用侧栏仍可进行完整的标题链接查询。
- 两个文本导入入口原先都在界面线程将 Markdown 全量转成编辑器结构，其中一个入口随后又重新序列化全文。现在直接保存规范 Markdown 正文和空编辑缓存，列表预览只处理前 4096 字符；打开时沿用后台解析与缓存。TXT 保留字面字符与换行，HTML 继续沿用现有清洗和转换规则。
- Tiptap 3.28 的表格、有序列表、任务列表 tokenizer 对不匹配的普通段落仍会拆分全部剩余正文，形成重复全量扫描。共享解析器和编辑器都使用快速首行/第二行检查，通过后仍调用上游 tokenizer，保留编号、罗马数字、嵌套待办及表格代码内竖线的处理。
- 大文档的视口包含样式原先等编辑器 `onCreate` 才启用。现在从初始内容的块数量决定首次挂载样式，避免先把整本书按普通文档布局。

## 后续范围：按需阅读、章节编辑

用户明确改选第二种方案：大笔记以连续阅读为主，屏幕附近按需挂载，需要修改时进入当前章节编辑，保存后回到阅读。普通笔记保留原编辑流程。首轮的 CSS 视口包含优化不能替代真正的按需加载。

实现：20 万字符及以上的本地/WebDAV Markdown 返回轻量正文句柄；Worker 仅建立块位置和标题索引，正文保留原样。阅读视图只挂载可见区域上下约 1000px 的小块，其余为保留高度的占位。默认块目标 6000 字符；单一超长代码/表格等结构按原文分片显示，避免构造巨大富文本节点。章节不超过 8 万字符时复用原编辑器，更长章节使用 Markdown 文本编辑。实时协作服务器启用时保持原有授权和完整协作编辑路径。

章节保存以完整原文版本和字符区间做原子校验，只替换该区间，保留其他部分逐字不变。发生并发更新时不覆盖新正文，把本次尝试保留为本机版本历史中的恢复版本。完整原文继续用于同步、导出、全文搜索和版本历史，运行时句柄不写入编辑缓存。
