# Notebook Next 数据接入与兼容性审计

审计日期：2026-07-22

## 结论

不要把旧版 `NotebookData` 或 `Database/notebook.store` 设成 Notebook Next 的数据目录。旧版是 SwiftData/Core Data SQLite + 附件目录，新版桌面端当前是 Chromium IndexedDB + 文件化配置；两者不是可原地打开的同一种数据库。

安全接入路径是：保留旧库只读备份 → 从旧版导出文档迁移包和同步信封 → 在 Notebook Next 导入 → 对照数量和附件校验 → 验证新同步 → 最后才切换日常使用。

## 数据目录

Electron 设置页会显示当前数据目录，并提供“更改数据目录并重启”。也可以在启动前使用：

```text
Notebook Next --data-dir=/absolute/path
NOTEBOOK_NEXT_DATA_DIR=/absolute/path Notebook Next
```

优先级为命令行、环境变量、设置页保存值、系统默认目录。路径必须是绝对路径。

系统默认目录遵循 Electron `userData`：

- Windows：通常为 `%APPDATA%/Notebook Next`
- Linux：通常为 `$XDG_CONFIG_HOME/Notebook Next` 或 `~/.config/Notebook Next`
- macOS：通常为 `~/Library/Application Support/Notebook Next`

更改目录只改变 Notebook Next 下次启动的位置，不会搬运已有数据，也不会转换旧数据库。已有新端数据应先“导出完整备份”，切换后再导入。

## 已核对的旧库

只读恢复副本中确认存在 13 类业务实体：资料库、文件夹、标签、笔记、块、附件、版本、笔记同步状态、后端同步状态、笔记删除墓碑、资料库墓碑、笔记标签、阅读位置和 Todo 步骤。

本机恢复副本计数：129 条笔记、83,685 个块、7 个主附件、1,227 个历史版本、76 个阅读位置、25 个笔记删除墓碑、20 个文件夹、6 个标签、5 个 Todo 步骤。该计数仅用于迁移验收，不修改源库。

## 兼容矩阵

| 数据 | 状态 | 说明 |
|---|---|---|
| UUID、标题、文件夹、标签、时间、回收站状态 | 支持 | 保留旧 ID；迁移包与同步信封均可导入 |
| 正文块、表格、任务块、代码、引用、附件引用 | 支持 | 转换为 Tiptap；原始旧文档同时保存在 `legacySource` |
| 字体、字号、字距、基线、段落间距等旧富文本细节 | 保留但未全部渲染 | 原始字段无损保存，当前编辑器只显示其支持的样式 |
| Todo 到期、完成、重要、步骤、排序 | 支持 | 已映射到新领域模型 |
| 主附件与音频 sidecar | 支持导入/备份/同步 | sidecar 作为隐藏子附件保存，不在普通附件列表重复显示 |
| 阅读位置 | 支持 | 通过旧同步信封导入 |
| 历史版本 | 支持 | 通过旧版本同步信封导入为 Revision；普通文档迁移包本身不含历史 |
| 删除墓碑 | 支持 | 通过 note index/library envelope 导入 |
| 旧同步状态和后端游标 | 归档保留，不复用 | 原始状态放入迁移元数据；新协议重新建立游标，避免把旧后端版本误当成新服务版本 |
| 隐私文件夹映射 | 支持 | 锁定笔记 ID 可从 library envelope 识别；旧 Keychain 密码不导出，需要在新设备设置本地访问密码。SSH 同步使用 SSH 密码派生的 AES-256-GCM 密钥保护笔记信封 |
| 直接打开 `notebook.store` | 不支持且禁止 | 必须经过只读转换；不能让 Electron/IndexedDB 写入旧目录 |

“完全兼容”应区分可恢复数据与完全一致呈现：当前可保留迁移协议公开的内容和原始富文本载荷，但不能从普通文档迁移包恢复它从未包含的 1,227 个历史版本、旧后端游标或系统 Keychain 密钥。历史必须同时提供旧同步信封，密钥必须人工重建。

## 新同步检查

元数据同步目前覆盖笔记本、分区、页面、正文文档、版本、标签及页面-标签关系、任务步骤、附件元数据与二进制内容、页面链接和阅读位置。产品不再提供知识图谱、画布或评论，因此新协议不再产生这三类数据；旧备份中的对应字段只为兼容读取而保留，不会进入当前界面或继续同步。

已验证：

- outbox 幂等重试和同实体合并；
- 乐观版本冲突；
- 分页拉取与游标推进；
- 正文 push/pull/delete；
- 页面永久删除时关联正文、步骤、附件、链接等本地清理与远端删除排队；
- 附件二进制上传、下载、删除和 100 MB 上限；
- 无附件内容时阻止“只有元数据”的不完整推送；
- 断网时保持离线队列，不把失败当成功。

Yjs 实时协作和元数据同步是两条互补通道：正文会进入普通同步，在线编辑时还可通过 Yjs 获得实时合并和光标状态。

## 推荐接入顺序

1. 退出旧应用，复制整个旧 `NotebookData`（包括 `notebook.store-wal`、`notebook.store-shm` 和 `Attachments`），保留只读原件。
2. 用旧应用导出“文档迁移包”；如需历史、阅读位置和墓碑，再复制/打包旧 SSH 或本地目录同步仓库中的 library envelope、note envelopes、note index、reading positions 与附件。
3. 给 Notebook Next 选择一个全新的空数据目录，绝不能选旧 `NotebookData`。
4. 先导入迁移包，再导入同步仓库包；重复 UUID 会更新同一记录，历史和墓碑会补入。
5. 对照本报告中的旧库计数，并随机抽查富文本、Todo、图片、音频 sidecar、已删除笔记和至少三个历史版本。
6. 导出一份 Notebook Next 完整备份并重新导入到第二个空数据目录，验证可恢复性。
7. 在测试工作区做双设备 push/pull、冲突和删除演练后，再启用正式同步服务。
