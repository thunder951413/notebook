# 同步性能优化与验证（2026-09-04）

范围：Electron 桌面端、共用 renderer/storage；不更改 v4.1 远端格式，不清空远端，不重置游标。本轮未修改 Android 独立实现。

## 已实现

- 普通写入在停止修改 60 秒后合并同步；持续写入最多等待 5 分钟。正文仍先写入本地事务性 outbox，不因等待而丢失。
- 无待上传内容时，失焦、退出和写入定时器不联网。前台事件最多每 2 分钟检查一次远端；启动、网络恢复和手动同步可直接检查。没有周期性的空闲轮询。
- 同步进行中的自动事件共享同一次执行，不追加一次无条件同步。新编辑由 outbox 及结束后的待同步检查续排；手动操作仍可排在当前任务之后。
- 失败重试间隔为 1、2、4、8、15 分钟，上限 15 分钟，成功后重置。冲突暂停自动重试；自动同步开关关闭时不重试。手动操作可立即重试。
- 标签、任务步骤、链接只为变化项生成 outbox；阅读位置未移动时不为更新时间生成新记录。完全相同的已排队写入保留操作 ID；真实新编辑使用新 ID，避免被旧上传确认误删。
- 编辑器退出保存时，正文和页面仅时间戳变化则不生成上传记录；保持原版本，清理已保存草稿但保留更新的草稿。
- WebDAV 上传确认时，仅将同一实体、同一已确认父版本上的后续本地编辑接到新版本上，保持待同步状态；不放宽远端分支冲突检测。
- 拉取不再执行 MKCOL。目录缓存、对象存在缓存按连接凭据隔离，5 分钟到期且有数量上限；PUT 遇到目录消失时清缓存、补目录，最多重试一次。
- head 缓存只接受强 ETag，首次 GET 的 ETag 必须与目录返回的一致。每轮仍读取真实目录；标记有变化立即重读。弱/缺失 ETag 回退正常 GET，不依赖修改时间或大小推断未变化。
- 小元数据最多 200 条合并成一次提交；附件/正文对象每批最多 25 个唯一哈希、8 MiB；新增内联日志目标上限 256 KiB。超过字节预算的单条记录独立一批。相同哈希在批内只传一份。
- 上传回执不完整时不确认 outbox。保留 60 秒单操作、180 秒整轮上限及每批持久确认；不取消上传后的并发检查。
- 完全没有远端记录和本地确认的同步不再触发全库 UI 重载。

## 可复现验证

真实 HTTP 内存 WebDAV 服务测试，不使用真实用户笔记作为性能样本：

| 场景 | 原行为 | 优化后的验证结果 |
| --- | --- | --- |
| 200 条小标签记录 | 8 次日志提交 | 1 次，减少 87.5% |
| 上述空仓库样本的 PUT 正文总量（日志 + head） | 8 次累计重写 | 小于原来的 25%，减少超过 75% |
| 强 ETag 未变、游标已消费、缓存有效 | MKCOL + 目录 + 每设备 head | 仅 1 次 PROPFIND，不 GET 日志/对象 |

| 未变化的标签/步骤/链接/阅读位置 | 重新入队 | 0 条新 outbox |

额外覆盖：强标记变化、弱/缺失标记回退、目录被删除后的恢复、失败批次不误确认、5 MiB 附件拆批、持续编辑最大等待、退避重置、手动绕过节流、自动事件合并、无变化不重载、上传中编辑保留。

## 边界与取舍

- 上述百分比是固定测试样本，不是所有笔记库或网络环境的保证。
- v4.1 在有本地变化时仍会重写本设备压缩后的日志；本轮通过减少批次数降低这部分流量，没有宣称实现 v5 不可变分段。
- 60 秒合并窗口用跨设备实时性换取更少请求。失焦有本地变更、手动同步仍可提前发布；网络失败时等待遵循退避。
- 持续停留在前台且没有本地变化时不定期拉取远端；需要即时接收另一设备修改时可手动同步。
- 新版 macOS 包本机安装验证；Windows/Android 的设备级测试与 release 不在本轮验证范围。
